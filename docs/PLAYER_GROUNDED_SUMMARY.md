# 有证据支持的选手总结 v1

画像接口新增 `profile.brief`，画像页自动显示首杀、首死和补枪总结；自然语言查询复用同一个确定性生成函数，并可聚焦首杀、首死、补枪、道具、致盲、下包六类行为。没有远程模型调用，不依赖提示词约束模型来保证数值正确。

## 结论与证据

- 基础表现保留比赛 / 地图 / 回合数、名单确认与估算数、K/D 原始击杀和死亡数、每百回合击杀及其分母。
- `claims` 按选手和行为记录筛选条件、样本规模、观测 / 未观测两组的原始计数、已知结果分母、胜率、文本和 `citation_ids`。
- `evidence_refs` 把每条引用绑定到观测 / 未观测组和胜 / 负 / 未知结果。相同回合的不同选手有不同引用 ID，保留各自队伍与结果。
- `sample_scopes` 提供各选手筛选、比赛 ID、样本量、分母质量、日期状态与基础指标，方便按原接口复查。完整参赛 ID 保留在画像的 `sample_scope.participation_round_ids`。
- 引用按每名选手、每种行为、每组结果固定选择一个示例，去重只合并同一选手的相同回合。统计用完整参赛集合；引用不是完整统计证据或随机样本，也不能独立证明未发生某个事件。
- 无某行为记录时明确输出 0 个观测回合及不可计算的观测胜率，引用标记为“未观测到”组；不切换到其他行为。没有参赛样本时不生成简报。
- 未知结果不记作负，日期缺失不推断“最近状态”；名单估算保持可见。取消按 30 回合阈值生成的主观可信度档位，统一注明“未进行统计推断”。
- 两名选手的总结保留样本组成差异提醒，不由不同的汇总胜率推断能力高低。

## 复盘建议边界

建议限定为核查所列行为的回合、事件顺序和局势差异。当前统计不足以判断站位、补闪、沟通或职责存在问题；不再直接把“未形成补枪”解释为队形或同步问题。道具、致盲和补枪仍受解析与银标质量限制，致盲记录不等于有效助攻。

页面把选手简报的“训练重点”改为“复盘核查”，并提供可点击的回合来源。主题内的关键回合过滤保留观测 / 未观测分组；点击引用使用已有时间线下钻。

## 验收

```bash
.venv/bin/python -m pytest -q
npm --prefix frontend run build
.venv/bin/python scripts/evaluate_player_queries.py \
  --dataset datasets/evaluation/player_summary_queries_v1.json \
  --output /tmp/player-summary-eval-new.json
```

- **119 项离线测试通过**。新用例覆盖六类主题、无行为记录、无参赛样本、未知胜负、旧名单估算、画像与自然语言共用结果、同回合不同选手归属。
- 检查器会拒绝错误统计值、错误引用组和缺失的应有引用。按队伍区分同一回合的胜负，防止引用 ID 存在却不能支持当前结论。
- **26 / 26 查询工程验收通过**：包含原有 20 条查询及新增 6 条行为总结查询。检查筛选与数值、结构化结论、引用归属、主题一致性和下钻；报告记录数据集、评测器、图谱服务代码哈希。
- 前端构建通过；浏览器核验自动总结、无行为记录的定向查询及引用下钻。
