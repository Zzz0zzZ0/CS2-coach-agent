# 投掷事件有界调查与保守v3

本轮调查只检查目标旧Inferno `2394200`及已有8份专用投掷事件对照，全部使用冻结的demoparser2 0.41.3。v3导出复用已经保存的8对照账本，没有再次解析这些对照。没有增加比赛、模型或查询时刻，也没有修改v1/v2结果、论文或既有检索脚本。

## 1. `weapon_fire`位于哪个阶段

下列名称是本轮实际传给解析器的完整字段名：

| 字段 | 本轮使用方式 |
| --- | --- |
| `Grenade.m_bPinPulled` | 拔销状态，检查事件前后true/false变化 |
| `Grenade.m_fThrowTime` | 记录的计划释放时刻；与同一帧的引擎时钟比较 |
| `CCSPlayerController.m_nTickBase` | 玩家引擎刻计数，不能直接当作Demo的`tick` |
| `game_time` | 引擎时间；下表所取帧与TickBase/64相等 |
| `health`、`team_name`、`active_weapon_name` | 在相应刻检查存活状态、阵营及手持道具 |

目标Demo一组正常闪光记录：

| Demo刻 | TickBase | game_time（秒） | PinPulled | ThrowTime | 观测 |
| ---: | ---: | ---: | --- | ---: | --- |
| 3671 | 39131 | 611.421875 | true | 0 | 动作启动前 |
| 3672 | 39132 | 611.437500 | false | 611.5257568359 | `weapon_fire` |
| 3677 | 39137 | 611.515625 | false | 611.5257568359 | 尚早于计划时刻 |
| 3678 | 39138 | 611.531250 | false | 0 | 首次出现闪光实体 |

这里`weapon_fire`与拔销状态true→false、登记未来释放时刻同刻，可描述为投掷动作启动的记录；它没有保证弹体已经离手。没有记录到原始按键输入，因此不把它断言为精确鼠标松键时刻，也不推广为所有补丁的API保证。

## 2. 唯一未配对firing为什么不是整Demo数据缺失

目标Demo共483条道具`weapon_fire`，482条有正常实体配对。唯一未配对的是R7的T方燃烧瓶，发生于开局83.15625秒，晚于该回合所有冻结查询。

| Demo刻 | TickBase | game_time | health | PinPulled | ThrowTime |
| ---: | ---: | ---: | ---: | --- | ---: |
| 60306 | 95766 | 1496.343750 | 3 | true | 0 |
| 60307 | 95767 | 1496.359375 | 3 | false | 1496.4481201172 |
| 60310 | 95770 | 1496.406250 | 3 | false | 1496.4481201172 |
| 60311 | 95771 | 1496.421875 | 0 | 无手持道具 | 无手持道具 |

死亡发生在登记的计划释放时刻之前。局部连续帧验证了TickBase每Demo刻增加1且`game_time=TickBase/64`。换算为`64×ThrowTime−TickBase_at_fire≈5.6797`刻；若该局部关系继续成立，首个不早于计划时间的Demo刻约为60313。实际死亡60311更早。不能直接把`ThrowTime×64`当Demo刻，因为两者有计数偏移。

这是与计划释放被死亡打断一致的原生证据。本轮适配只使用这个已核对且位于冻结查询范围外的案例，不把所有缺少实体的firing自动当作取消，也不套经验6/7/14刻延迟。

## 3. 三个无firing实体与死亡的关系

目标Inferno的3个额外实体均在所有者死亡同刻出现。前一刻所有者仍活着、手持相符道具，PinPulled为true、ThrowTime为0；死亡刻health变0，手持道具字段消失。

| Demo刻 | 类别 | 当时阵营 | 所在查询范围 | 处理 |
| ---: | --- | --- | --- | --- |
| 97537 | 闪光 | T | R11，开局12.953125秒 | 不增加CT投掷计数 |
| 183539 | HE | CT | R20，开局11.03125秒 | HE专用事件语义尚无类型内反例，之后查询保留未知 |
| 188352 | HE | T | R20，开局86.234375秒 | 查询范围外，且不是CT投掷 |

这些字段支持已拔销道具随死亡产生实体的机制，但不能仅凭“同刻死亡”推断所有类别的专用事件行为。

| 对照Demo | 正常释放 | CT查询计数相符/总数 |

| 2399384 | 275 | 70/70 |

| 2399386 | 535 | 120/120 |
| 2399387 | 512 | 110/110 |

8/8对照的3553个正常释放均与原生`grenade_thrown`在刻、玩家、道具、阵营上完全对应；CT累计计数830/830相符。这里的正常释放不包含两个额外死亡掉落实体。

两个死亡掉落反例分别是2398718的45017刻和2399384的7297刻，**均为烟雾**。两者同样有前一刻PinPulled=true、ThrowTime=0及同刻死亡/实体出现；专用`grenade_thrown`中确实没有同玩家同刻的记录。后者解释了v2派生中被保留为歧义的两个查询时刻。

因此，烟雾死亡掉落可以作为本组数据中有直接反例支持的排除规则；本轮没有把它外推为HE规则。没有增加数据去寻找HE反例。

## 5. 最小v3与接入

v3基于完整v2情境，仅更新目标Inferno：保留482组正常释放，按实体出现时刻和原生阵营统计。取消释放的T方案例处于83秒；T方额外实体不算CT使用。CT HE异常后仍未知。

结果为**245/246个完整道具情境窗口**。Inferno新增19个完整窗口；R20仅10秒已知，12/15/18/20秒仍未知。共新增96个已知查询快照。其余226个v2完整窗口及所有装备、比分、时刻、顺序均保持原值。

- 导出脚本：`scripts/export_ct_independent_context_v3.py`
- 固定协议：`datasets/selections/ct_independent_context_v3.json`
- 情境：`output/tagnet/ct_independent_context_v3/context.json`
- 报告：`datasets/evaluation/ct_independent_context_v3_report.json`
- 原始有界账本：`datasets/evaluation/ct_utility_event_investigation.json`

最小重放接入只需让后续原定检索、联合模式迁移读取v3情境，并写入各自独立v3输出目录；源context、源权重、聚类中心、七项策略及查询集合均不变。此导出复用已有8对照账本，未再次解析对照、未运行模型或排名。脚本拒绝覆盖输出，内含边界自检和非道具字段不变断言。
