# 关系与时序开发评测 v1

当前题组针对此前简单题的两个缺口：候选回合全部相关，以及负例候选范围为空。新增 24 个独立题意、48 个中英文表述，覆盖首杀主体、下包后定向击杀、限时补枪三类，各有 4 正例与 4 负例。全部题目均有 17–30 个有效候选回合，正例只有 1–4 个相关回合，且每个正例和负例均有不满足关系条件的近似事件。

这是 AI 逐源审核的开发题组。先查看既有数据的事件计数，选定 4 场比赛的 Nuke、Dust2、Ancient、Mirage 共 88 个回合范围；不是随机抽样、未见测试或人工 gold。翻译不增加独立样本量，同场问题也不具备统计独立性。标签基于共享解析事实，Python / SQL 一致仍可能共享解析错误。

## 冻结材料与定义

- [协议](../datasets/evaluation/relation_v1_protocol.json)、[中英文问题](../datasets/evaluation/relation_v1_queries.json)、[完整相关集与近似反例](../datasets/evaluation/relation_v1_qrels.json)、[源数据审计](../datasets/evaluation/relation_v1_source_audit.json)。旧问题、标签、报告保持不变。
- **首杀**：指定选手击杀指定对手，且源事件 `is_first_kill=true`。两名选手仅在场不算满足关系。
- **下包之后**：指定主体击杀指定对手的 tick，严格大于该回合同一次炸弹安放的 tick。相等不算之后；下包者可以是任何人。
- **补枪**：被击杀队友、补枪者、敌人三人身份不同；队友与补枪者队伍相同，并不同于敌人。补枪者在队友死亡后 `0 < tick 差 <= 320` 时击杀同一敌人。本轮直接问 320 ticks，不从录制帧率推断时间。
- **负例**：穷举完整的比赛、地图和参赛主体范围后没有相关回合。首杀负例保留普通定向击杀，下包后负例保留下包前击杀，补枪负例保留超过 320 ticks 的同一敌人反杀。

全量 42,148 个源事件与只读 SQLite 完全一致；从原始回合名单重建选手身份和候选范围，检查 528 个问题×回合组合。每题的完整相关事件 ID 和近似反例事件 ID 均保存，示例同时保存主体与 tick。没有用检索结果选题或改标签。

## 方法与信息边界

共同语料仍为 1,019 个历史回合。新文本按 tick 排序，明确击杀主体、对手、队伍、阵营与下包时点，保留道具和受闪事实；没有预先写入“补枪成功”“下包后击杀”等答案标签。原始语料 JSONL 位于 `data/evaluation/relations_v1/corpus.jsonl`，保留相同事件及来源路径。该表示与旧 fair v2 不同，不能把不同题组之间的分数变化归因于算法改进。

BM25、多语 MiniLM dense、RRF 使用相同文本、相同显式比赛 / 地图 / 名单过滤、top-5 与固定参数。原始中文和英文分开报告，暂不加词表。自然语言排序函数不接收关系条件、正负标签或 qrels。共同正确范围是实验输入，因此本轮不测自然语言范围解析能力。

关系 SQL oracle 单列，它得到正确结构条件并执行精确连接，只用于标签和可达上限检查，不代表生产 GraphRAG，也不是公平的自然语言竞争方法。旧的只按事件类型筛选的 SQL / 简单图路径输出不纳入本轮结果。

文本基线尚无经校准的拒答机制。无答案误召回率反映当前 top-k 管线行为，不能据此宣称向量模型天然不能拒答。正例 nDCG@5、Recall@5 与负例误召回分开，先按题意平均语言结果，再计算宏平均。每种文本方法重复检索 3 次检查确定性；模型完全使用本地缓存，远程模型调用为 0。

```bash
PYTHON_DOTENV_DISABLED=1 HF_HUB_OFFLINE=1 .venv/bin/python -m scripts.benchmark_relations run \
  --model-dir /absolute/path/to/frozen/local/model \
  --output data/evaluation/relation_reproduction/report.json
.venv/bin/python -m scripts.audit_relation_benchmark \
  --report data/evaluation/relation_reproduction/report.json \
  --output data/evaluation/relation_reproduction/audit.json
```

命令必须在冻结源码版本和项目根目录运行，输出路径必须未存在。协议锁定语料、图谱、问题、标签、源码及本地模型文件 SHA；运行前后验证。公开仓库不包含 Demo、完整本地语料或模型文件，复现需先取得对应资产，路径和哈希见协议。

## Verdict

工程验收通过，检索质量仍有明显短板。问题、标签和实现先在 `f22a0bc` 冻结并推送，随后完成 48 个表述 × 4 种输出共 192 条结果。冻结提交的 [CI](https://github.com/Zzz0zzZ0/CS2-coach-agent/actions/runs/34073963126) 通过 172 项测试、依赖检查及前端构建。完整 [结果](../datasets/evaluation/relation_v1_report.json) 与 [运行后审计](../datasets/evaluation/relation_v1_result_audit.json) 保留全部失败。

## 实际结果

表中正例指标各有 12 个语义问题；先平均同题中英文，再宏平均。负例另有 12 个语义问题。每个正例相关回合只有 1–4 个，因此 Recall@5 的理论上限均为 1。

| 方法 | 正例 nDCG@5 | 正例 Recall@5 | 负例误召回率 |
| --- | ---: | ---: | ---: |
| BM25 | 0.1492 | 0.2569 | 100% |
| Dense | 0.1476 | 0.2188 | 100% |
| Dense + BM25 RRF | 0.1118 | 0.1319 | 100% |
| 结构条件 SQL oracle（非竞争方法） | 1.0000 | 1.0000 | 0% |

| 方法 | 英文 nDCG@5 | 中文 nDCG@5 | 首杀 / 下包后 / 补枪 nDCG@5（语言平均） |
| --- | ---: | ---: | --- |
| BM25 | 0.1330 | 0.1654 | 0.1734 / 0.0587 / 0.2155 |
| Dense | 0.1827 | 0.1124 | 0.2246 / 0.1971 / 0.0210 |
| RRF | 0.1118 | 0.1118 | 0.2193 / 0.0740 / 0.0420 |

正确相关回合都在共同候选范围内；全部返回来源也都在正确范围内。当前错误出在范围内选择证据及缺少拒答机制，不能再用空范围过滤效果代替关系能力。

运行后描述性分析：BM25 / Dense / RRF 在 24 个正例语言表述中分别有 13 / 14 / 16 个 top-5 完全未命中。因此仅给当前 top-5 加关系过滤会丢失许多有答案问题，需要扩大到可控的候选范围，或先改善事件级候选召回。此分析没有修改任何排序。

例如 `trade_1_positive`：Nuke 比赛 2396949 第 1 回合，NiKo 在 tick 11243 击杀 zont1x，donk 在 11385 击杀 NiKo，间隔 142 ticks；第 11 回合 donk 为 zont1x 击杀敌人的延迟为 1341 ticks，属于近似反例。英文 BM25 将正确回合排第 4，dense 的 top-5 完全漏掉。负例 `after_plant_1_negative` 中 TeSeS 对 tN1R 的击杀在下包之前，范围内没有所问关系，但三种文本方法仍返回回合。

新文本共生成 8,197 个分块，最多 128 tokens、正文分块 118 tokens，等权均值后归一化。语料编码约 110.18 秒；检索计时和查询编码耗时保存在每条结果中，SQL oracle 本轮未计时，不作为效率对照。运行环境为 Python 3.11.15、FastEmbed 0.8.0、ONNX Runtime 1.29.0，模型及依赖证据见 [环境记录](../datasets/evaluation/relation_v1_environment.json)。

## Findings

- **major / high，范围内关系检索质量不足**：`relation_v1_report.json` 中三个文本基线的正例宏平均 nDCG@5 为 0.1118–0.1492，补枪 dense 仅为 0.0210。源审计确认相关事件存在且候选范围包含它们，当前文本表示和排序不足以可靠选择该类证据。下一步需独立验证关系解析、事件级召回与证据筛选。
- **major / high，当前 top-k 管线不拒答**：12 个有效范围无答案题、两种语言中，三个文本方法的误召回均为 100%。该管线没有校准拒答条件，所以下一步先建立可审计的关系不成立 / 未知状态；不能只给现有 top-5 加过滤后就宣称解决，因为正例也频繁完全漏召回。
- **minor / high，融合未体现增益**：本题组 RRF 的 nDCG 和 Recall 均低于两个单独基线。保持这个结果，不预设融合更强，不在已跑分问题上调融合参数。

未发现当前题组的空候选负例或候选全部相关正例。对 24 题逐题查看正例与近似反例事件，确认中文与英文都明确了主体、对手和时序 / 窗口。15 项新增测试覆盖窗口 0 / 1 / 320 / 321、反向时间、错误主体 / 对手 / 队伍、自身补枪、严格下包时序及文本字段保留。

## Verified

172 项测试通过。24 题、528 个候选问题×回合组合的 Python / SQL 判断和事件证据一致，88 个不同回合的名单范围与原始 SQLite 一致。原 1,019 回合非文本字段完全保留，42,148 个事件与原始 SQLite 相同。192 条结果的范围、完整相关集、指标和语义组分母全部复核，文本排序连续 3 次一致，输入哈希运行前后不变。生产 SQLite / Milvus、常驻 API 与 Worker 未改动；远程模型调用为 0。

## Risks

样本是按已观察源数据构造的，同一比赛的问题相关，不能用于独立泛化或总体置信区间结论。仅 3 类关系，不包含跨回合画像统计。中文词法、长文本均值向量与自然语言关系解析仍是待评估项。AI 标签不替代 CS2 专家对战术建议的质量评审。

## Next actions

1. 优先建立自然语言到主体、对手、时序 / 窗口的受限解析与事件证据验证，分别表达“关系成立”“限定范围内不存在”“信息不足 / 不支持”。用另设的开发反例覆盖角色互换、同 tick、窗口边界、跨回合和缺失信息；本轮 24 题保持观察过的回归身份。
2. 召回与验证分别验收。首先确保可控范围内的相关事件不被 top-5 提前丢弃，再给 BM25 / dense / RRF 共用相同验证条件，单独测解析错误、漏召回与误拒答。人工提供的结构条件继续单列 oracle，不泄漏给自然语言对照。
3. 在相同新题组上另行冻结事件文本与中文词法 / 多语 dense 的表示实验，验证更合适的基线；跨回合画像统计单独扩展，不把现有三类题覆盖宣传成全面战术理解。正式新比赛测试和求职 / 港硕展示材料仍需保留样本、标签和方法边界。

代码检查也支持该优先级：生产 `GraphRAGService._round_score` 当前以事件类型、战术标签和身份词命中加分，没有执行上述定向主体与时序约束；本轮未将其当作实验方法或修改生产实现。后续必须实际测量自然语言生产路径，不能把本轮 SQL 满分挪作生产成绩。
