# TAGNet 泛化与 CS2 Coach 接入方案

日期：2026-10-22（原始方案），执行进度更新至 2026-10-23。当前已完成源版复现、共同特征训练和 [CT 数值泛化矩阵 v7](CT_GENERALIZATION_CONFIRMATION_V7.md)：9 系列、465 回合、41 个评估折。当前图模型未证明优于简单线性对照；完整地图语义、独立战术相关性、T 方训练仍未验收，真实后端按用户要求暂缓。本文保留原始规划，不把现有粗状态探针等同于全部研究目标已实现。

## 1. 目标、范围与成功定义

目标是学习 CT 开局防守的空间与时间表示，为 CS2 Coach 提供可追溯的相似回合、地图内阵型分布和队伍风格对照。第一版仍采用冻结结束后 10/12/15/18/20 秒五个快照。

必须区分以下能力，分别报告结果：

| 层级 | 实验 | 可以声明的能力 |
| --- | --- | --- |
| G1 | Dust2 模型处理未参与开发的新比赛 | 同地图跨比赛、跨时间泛化 |
| G2 | 每张地图分别训练与聚类 | 多地图适配；不能据此声明跨地图迁移 |
| G3 | 共享模型处理训练过的地图中的新比赛 | 已见地图上的统一表示 |
| G4 | 留出整张地图，冻结模型后测试 | 对该留出地图的零样本迁移 |
| G5 | 在留出地图少量比赛上适配，再测其余独立比赛 | 少样本适配；与 G4 分开 |

推荐顺序：G1 → Dust2/Ancient 的 G2 → 至少三张地图的 G3/G4。G5 仅在 G4 不足时开展。T 方开局列为并行数据准备、独立建模与评测的扩展，见第 13 节。普通玩家、全回合、实时建议不纳入本轮验收。模式分布与胜率的关联不等于策略收益。

## 2. 已核对的起点

上游事实：发布模型使用 Dust2 区域 one-hot、血量和装备特征，以玩家距离驱动图注意力，再输出回合表示。训练损失依赖快照解码头，情境编码器和 GRU 不受该损失训练。原版必须保留为忠实基线；新增时序训练是本项目的研究变体，不能算作上游已有能力。[训练源码](https://github.com/weyoung-open-lab/TAGNet-CS2/blob/main/scripts/train_tagnet.py)

上游分析在全部发布回合的表示上聚类；这适用于探索性描述。本方案的泛化评测需要另外冻结训练集中心，不能照搬该流程到测试集。[聚类源码](https://github.com/weyoung-open-lab/TAGNet-CS2/blob/main/scripts/analyze_results.py)

本仓库 `datasets/silver/v0.3/round_annotations.jsonl` 的当前静态记录：

## 3. 数据获取、去重与独立划分

### 3.1 三个数据用途

1. 上游发布数据与权重：仅用于原版复现、接口一致性和源域基线。保留许可证、来源与文件哈希。
2. 当前仓库候选比赛：用于解析开发、地图适配和初始训练。已经查看、调试过的数据标为开发数据。
3. 协议冻结后另行保留的新比赛：用于正式泛化评测；对比赛日期、队伍、地图版本和经济分布分别统计。

每场记录 `series_id / match_id / map / played_at / event / teams / demo_sha256 / source_url / parser_version / map_geometry_version / split / exclusion_reason`。与上游数据按可核对的赛事、队伍、比赛日期及 Demo 哈希去重，身份不明的重叠列为 Unknown。数据清单与必要授权记录不包含密钥。

所有划分以整场 BO 系列为最小单位，同一系列的地图、回合和五个快照不跨集合。重赛、相同 Demo 的不同文件名和同一回合不同抽样不算新增样本。

初始开发可按系列约 70/15/15 划分，但小样本须逐地图列出实际系列数，不机械套比例。正式时间泛化使用更晚的新比赛；跨队伍测试另列一个协议，不把时间留出自动称为队伍留出。

G4 采用逐地图留一测试：模型、预处理统计、训练超参数都不能使用目标地图的比赛。地图几何等部署前可获得的静态资产允许使用，但要明确这是“有地图静态信息、无目标地图比赛”的迁移。超参数只在源地图内部验证，条件允许时用源地图间的内部留一验证。只有两张地图时可做探索，不能声称结果覆盖所有地图。

G5 从目标地图抽取 1/3/5 场适配系列，重复预先固定的抽样，测试系列始终隔离。源域预训练、少样本适配和测试数据用量全部公开。

### 3.2 数据量与停止条件

先提取现有候选数据并画按系列数增长的学习曲线，再决定补数据。建议把每张试点地图 15–20 个独立系列作为采集预算起点，不是统计充分性保证；稀有模式、版本和经济条件不足时仍需继续采集或缩小声明。

第一次开发运行后冻结正式样本量和停止规则：完成预定独立系列后统一评测；不根据测试胜负不断追加直到显著。样本不足时报告区间和探索性结果。

## 4. 快照契约与质量控制

复用 `TacticalDemoParser._parse_ticks` 按选定 tick 批量采样，避免全量轨迹导出。原始字段至少包括：

- 比赛、回合、冻结结束、回合结束、实际采样 tick 与时间偏差；
- 双方本回合名单、SteamID、阵营、队伍；五个时刻各玩家 X/Y/Z、区域、血量、装备值；
- CT/T 装备总值、截至该时刻的 CT 烟与燃烧弹记录、投掷区域、回合前比分和上一回合信息；
- 字段来源、缺失状态、地图版本、解析器与特征版本。

禁止把本回合最终胜者、结束原因、未来下包位置、20 秒后的击杀写入开局模型特征。胜者只用于事后对照。上一回合信息必须在回合开始前可知；换边和加时按实际比赛状态处理，不能仅凭回合号猜测所有经济状态。

源版复现和改进版分别保留明确口径：

| 情况 | 源版兼容路径 | 改进版 v1 |
| --- | --- | --- |
| 已死亡玩家 | 按上游保留记录，血量为 0 | 保留身份和观测，使用 alive mask 限制其对当前阵型的贡献 |
| 缺失玩家/坐标 | 不伪造记录 | 整回合跳过，区别于死亡 |
| 20 秒前已结束 | 不补造快照 | v1 跳过；以后再研究变长序列 |
| 区域名称不在词表 | 记录未知与原因 | 使用已定义的有效其他区域，无法判定则跳过 |
| tick 不匹配/暂停 | 检查与源版时间轴差异 | v1 要求可核对的目标 tick；无法确认有效开局时间则跳过 |
| 重复/替补/教练记录 | 核对本回合正式名单 | 去除非参赛记录，名单有歧义则跳过 |

默认以核验后的 64 Hz CS2 数据开展，不把默认值当作测量值。若 demo 时间轴、暂停或解析 API 与假设不符，先解决时间对齐，再扩样。区域位置 `last_place_name` 与上游 `place` 必须抽样对照，不能仅按字段名认为相同。

输出各地图、版本、队伍、经济和胜负下的 eligible/used/skipped 数及理由；展示覆盖率分母，避免只研究活到 20 秒的回合却声称覆盖所有回合。过滤规则对所有比较方法一致。

## 5. 模型路线：先最小适配，再共享

### 5.1 M0：源版复现

隔离环境使用发布权重、发布词表和归一化参数，重算固定样本表示并核对。论文六簇来自分析路径，训练时最佳 K 与之不同；固定对应的中心和名称映射。不得每次上传重新拟合 K-Means。

CPU/GPU 与重新训练带来的簇变化单列；复现发布权重与从头训练是两个验收项。[作者披露的复现边界](https://github.com/weyoung-open-lab/TAGNet-CS2/blob/main/README_zh-CN.md)

### 5.2 M1：每张地图分别训练

保留图注意力和五快照流程，为 Dust2、Ancient 分别建立本地 place 词表、归一化、模型及簇解释。每张地图单独确定 K。此阶段最快形成可用多地图对照，地图间的向量距离与簇编号不可直接比较。

先从头训练一个小模型；是否迁移源版中形状与含义一致的中间层只作为有明确增益后再做的实验。输入维度变化时不能声称完整加载源权重。无需一开始增加更多图层、Transformer 或自动架构搜索。

### 5.3 M2：共同语义特征与共享编码器

保留 3 层、宽度 64 的图注意力和 64 维回合表示作为起始配置。共同输入替换地图专有 place one-hot，起始定义如下：

| 内容 | v1 定义 |
| --- | --- |
| 玩家状态 | health/100、装备 log1p 训练集缩放、alive |
| 共同区域 | A 点、B 点、A 接近区、B 接近区、连接/争夺区、CT 出生区、T 出生区、其他，共 8 类 |
| 地标几何 | 到 A/B 几何参考点的距离，以及相对该地图固定高度基准的高度 |
| 边 | 玩家间 3D 欧氏距离、高度差；共享边偏置 MLP 使用对应输入 |

共同区域由每地图静态配置映射，记录定义、重叠消解优先级、未知区域和版本。区域是便于比较的粗粒度设计，不能预设不同地图的同名区域具有相同战术意义。

几何距离与高度按固定地图几何尺度归一化；尺度来源为地图资产，不从测试玩家分布估计。装备等数据统计只拟合训练集。缺失/异常值显式处理，不对测试集合重算 min/max。共同节点维数按以上定义为 14；边维数为 2，输入层和边偏置相应重训。

地图内标准化 X/Y、地图 ID 可作为 G3 对照特征；G4 主模型不依赖地图 ID 或目标地图专有可学习词表。上游已有 `xy/place_xy` 变体可复用作消融，不等于跨地图已经验证。[变体代码](https://github.com/weyoung-open-lab/TAGNet-CS2/blob/main/supplementary/train_variants.py)

欧氏距离不足以解释墙体、通道和楼层。v1 先在 Dust2/Ancient 验证；Nuke 只有在楼层与高度特征核对后加入。若出现“隔墙近、通行远”的系统错误，再增加可靠导航通行距离。导航距离与欧氏距离分字段、分版本，不能缺失时静默替换。导航资产取得性与标定仍为 Unknown。

空间快照经 alive mask 后池化，再按固定时间顺序输入 GRU。死人是已知状态，缺失是质量问题；二者不共用一个 mask。全部 CT 已死亡且快照仍出现时标为终止/不可用，不生成普通阵型。

### 5.4 情境与阵型分开处理

主检索表示先只编码站位、状态与时间。经济、比分、队伍和对手作为结构化过滤/分层条件；它们有助于比较，但也可能让模型只学会“同队/同经济”。队名、SteamID 不作为输入。

原版情境联合表示作为完整基线保留。只有在控制经济与队伍后的检索仍获益，才考虑把情境编码器加入改进模型；届时必须有从回合目标到情境编码器的梯度检查。条件相关性不能解释成战术原因。

## 6. 训练目标与最小实验矩阵

M2 主目标：`L = L_snapshot + lambda_time * L_next`，初始 `lambda_time=1`；只在验证集对比 0/0.5/1，固定后再开正式测试。

- `L_snapshot`：从当前快照表示重建八类区域的存活人数/5，以及存活玩家成对距离的均值和最大值。距离项在存活人数不足 2 时屏蔽；损失按有效目标数归一化，避免缺失被当成零。
- `L_next`：从前缀快照的 GRU 隐状态预测下一个快照的同一组目标。使用 10→12、10/12→15、10/12/15→18、10/12/15/18→20 四个训练样本，仍整体归属于原回合。
- 不允许 20 秒的输入参与预测 18 秒。编码器可并行计算各帧，预测路径必须只读取对应前缀。
- 推理时使用截至 20 秒的最终表示；18 秒前缀预测的质量与完整表示检索的质量分别报告。
- 下一帧预测需与“保持上一帧状态”的简单基线比较，避免仅靠站位变化缓慢获得好分。

该目标是待验证的最小设计，不保证比原版有效。它学到的是防守状态及其变化，不输出最佳策略。若只得到粗区域分布而缺少通道差异，先从错误回合决定是否增加目标，不提前堆叠对比损失。

| 编号 | 方法 | 目的 |
| --- | --- | --- |
| B0 | 五快照区域人数 + 距离统计，直接检索/聚类 | 判断神经网络是否必要 |
| B1 | 发布 TAGNet，Dust2 数据 | 忠实源版与新比赛迁移基线 |
| B2 | 地图独立模型 M1 | 最小产品适配基线 |
| B3 | 共同特征 M2 + 快照均值池化，无 GRU | 判断共享空间特征价值 |
| B4 | M2 + GRU，只有快照目标 | 隔离无时序训练信号的影响 |
| B5 | M2 + GRU + 下一帧目标 | 主候选 |

按顺序开展，不跑巨大组合网格。B0 与源版用同样数据、过滤和候选库；B3–B5 使用同样共同特征和训练预算。每项先跑固定 5 个随机种子，报告全部种子、均值和范围；资源不足明确降级为探索。训练从上游的小模型、AdamW 与早停设置起步，验证集用于停训。新增模型需记录梯度、损失曲线、表示方差及非有限值，检测未训练模块和表示塌缩。

聚类只服务解释，检索不以簇相同为硬条件。K 从预先固定的 2–10 范围在训练/验证侧选择，结合稳定性和解释性；测试集只分配到冻结中心。各地图分别聚类；跨地图检索先按共同表示评分并检查语义，不强制共用“六种战术”。

## 7. 评测协议与晋级门槛

### 7.1 三种独立检索问题

1. 同地图、不同系列：站位变化与关键区域控制是否相似。
2. 同地图、相同经济等条件：排除仅因经济接近获得相关性的解释。
3. 跨地图：只评价可比的抽象模式，例如双点分散、某点集中、连接区压迫；不能要求局部区域名一致。

查询是当前回合，候选历史库排除该回合及其所属系列。G4 的主评测使用源地图历史候选库；如果另设含目标地图样本的库，明确标为目标地图有参考样本的条件，不混成同一零样本分数。

正式评测先冻结相关性规范与查询清单。试点可从 60 个查询起步，按地图/经济/胜负/死亡状态分层；这是预算起点，不是充分性保证。候选池包括所有方法 top-k、规则分层抽样及随机负例，去重后隐藏方法与排序来源交给评审。至少两位熟悉 CS2 的评审独立审核一部分重叠样本，保留分歧和裁决；未获得审核时只能报告工程检查。

相关性分 0/1/2：无关、部分相似、明显相似。提供五帧位置和必要上下文，不把系统簇名或模型评分作为答案。评审不以同胜负或同队伍判定相似。

### 7.2 指标

- 主指标：同地图独立比赛 `nDCG@5`；辅助 `Precision@5` 和可提供合格结果的查询比例。
- 候选池未穷尽时说明评测池边界，不把池内 Recall 称为完整语料 Recall；不计算无正例查询的虚假满分。
- 按地图、经济、队伍、日期与质量分组，报告系列级 bootstrap 的差值区间和各组分母；样本过少时明确区间不稳定。
- 辅助：下一帧预测误差对比持久性基线；跨种子 ARI/簇规模；表示近邻与队伍/地图/经济的相关性；覆盖率、跳过原因。
- 工程：冷/热提取与推理 p50/p95、每回合向量检索时间、内存、存储、失败率。分别记录解析与推理，不沿用上游 CPU 时间估算。
- 对同一回合置换玩家槽位，同时置换边，应得到数值容差内一致的表示；改进版不使用槽位身份编码。时间序列打乱作为诊断，不预设“越变越好”。

### 7.3 门槛与失败后的去向

以下是拟议验收目标，正式测试前冻结，不能测试后改门槛：

| 阶段 | 晋级标准 | 未通过时 |
| --- | --- | --- |
| 数据 | 输入与来源可追溯；无跨集合重复；所有排除有原因；核心完整性用例通过 | 修解析或缩小地图范围 |
| G1/G2 | 模型与 B0 在独立查询上同条件比较；主指标差值的系列级 95% 区间下界 > 0，且不降低可用覆盖率 | 区间跨零则仅称效果未确定；产品采用 B0 或保留实验入口 |
| G3 | 对比 B2，预设主要地图上满足非劣目标；建议绝对 nDCG 容忍差 0.03，并报告区间 | 保留地图独立模型，不强推共享 |
| G4 | 在未见地图优于同条件 B0，且差值区间下界 > 0；逐地图展示，不用总体均值掩盖失败 | 转 G5 或声明需要目标地图训练 |
| 产品 | 版本/过滤/来源/降级/恢复契约通过；试点推理增量 p95 目标 ≤ 2 秒/场，检索 ≤ 200ms（先测基准机器再冻结） | 先离线构建或优化实测瓶颈 |

非劣目标指差值区间下界不低于 -0.03，而非只比较点估计。上述数值是项目选择，不是文献保证。增加数据、调参或改协议后的测试应有新版本，并保留旧失败；反复使用的测试集转为回归集。

## 8. 输出契约与模型发布

每回合独立的模型记录建议包括：`source_round_id / source_demo_sha256 / input_snapshot_hash / schema_version / feature_version / model_version / map_geometry_version / snapshot_ticks / status / reason / embedding_ref / cluster_id / cluster_version / distance_to_centroid / evidence_snapshot_ids`。

`status` 限定为 `ok / unsupported / insufficient_data / out_of_distribution / failed`；不支持地图与损坏数据分开。距离阈值在验证集校准，先报告覆盖率与相关性取舍；分布外距离只是警报，不是可靠概率。不能用 softmax(-distance) 冒充战术正确置信度。

模型结果独立于 `CanonicalEvent` 和现有银标。现有 `TacticalLabel.confidence` 必填，不能随手填 0.9 或 1；v1 不把聚类写成已确认事件。若未来新增模型标签，须同时定义非概率分数、审核状态、来源引用与展示语义。

发布包包含权重、训练配置、训练/验证清单哈希、特征与归一化、地图配置、冻结中心、簇名解释、验证结果、代码版本和许可。模型仅从受信本地路径加载，不接受用户上传任意权重；版本不匹配直接拒绝该模型步骤。

相似度 v1 采用固定版本表示的欧氏距离，特征基线先做训练集尺度处理；所有方法固定各自距离定义。改成余弦距离属于新评测版本，不能只修改线上分数。不同模型版本、地图独立模型之间的向量不能混查。

## 9. 与现有项目的最小接入

流程：`Demo → 现有事件解析 + 五帧快照 → 独立模型结果 → 同地图/经济过滤 → 相似回合 → 当前/历史来源下钻`。

先离线产出，不修改当前确定性报告。结果有效后，再加入现有任务流程与页面。第一版向量以本地 NumPy 文件和元数据索引存储，复用 SQLite 回合来源；小规模直接扫描。只有实测瓶颈出现后才考虑独立 Milvus collection，不与文本向量混用。

Webhook 没有可信快照时走原流程；如果以后允许传快照，需核验字段、版本、tick、名单与大小限额，并注明外部来源。模型失败保留现有报告，单独显示模型失败及原因，不能让已有 Verifier 的 pass 被误认为阵型模型也通过。

v1 不扩展 Coach 白名单。阵型检索独立展示，允许表述“在该模型表示下相近”；未来只有补充证据契约、事实核验和建议质量评估后，才把它用于训练主题或自然语言解释。相似回合的胜负是描述性对照，不能自动生成“应该采用某阵型”的建议。

## 10. 必须通过的检查

数据：固定 tick 与时间偏差、区域映射、死亡/缺失区别、名单更换、换边/加时、提前结束、暂停、重复 ID、源文件哈希。

模型：源版固定样本推理一致性；共同输入维数；mask 正确；有效参数有梯度；未来信息不进入前缀；非有限值拦截；玩家置换不变性；缺失训练特征不能静默补零。

评测：系列隔离；归一化/词表/中心只拟合许可集合；自身系列排除；同模型版本比较；无候选与分布外状态；qrels 来源与候选池记录；系列级统计。合成 fixture 明确标为“模拟示例”，不作为真实比赛效果证据。

集成：默认关闭兼容现有结果；上传清理前持久化；刷新恢复；过期请求隔离；不支持地图降级；失效模型包；任务结果与来源版本一致。只运行与新增逻辑相关的离线测试，再按晋级阶段做真实 Demo 验收；文档交付阶段不声称已跑这些检查。

## 13. T 方开局的扩展方案

### 13.1 复用范围与单独验证范围

五人图、距离感知注意力、前缀时序预测、快照数据契约和独立比赛协议可以复用。T 方需单独数据、训练、簇解释和检索评测；不能直接给 T 方分配 CT 的六类防守名称，也不能把 A/B 坐标镜像当作攻守转换。

第一步同时提取 CT/T，保存 `side` 并按阵营分别统计覆盖与失败。训练、聚类、候选检索默认按阵营隔离，跨阵营向量相似性不作为产品功能。先做独立 T 模型；只有 CT/T 各自基线均完成，才把共享主干、阵营条件化作为消融，不预设共享会更好。

### 13.2 T 方开局任务

目标是检索“开局站位与移动展开相似的进攻回合”，例如分散展开、多人集中于一路、连接区域控图变化。这些是待审核的空间描述，不代表已经识别 rush、假打、默认战术或最终进攻意图。

v1 同样使用 10/12/15/18/20 秒，便于复用数据和公平比较；这只能覆盖早期开局状态。T 方早期慢展开或尚未决定进攻方向属于合法状态，不强行归入 A/B 进攻。后续若研究更长开局，必须另设截至 30/45 秒的任务与前缀截断规则，单独分析提前结束和下包造成的选择偏差，不能看完回合再选择“最佳开局窗口”。

共同区域、存活人数、队形离散程度和到地标的距离先作为基线。可增加仅在该快照直接观测到的持包状态、队伍道具与位移变化，但每个新字段必须核对解析支持与时间因果。最终下包位置不能作为开局持包路线标签。

当前属于离线 Demo 复盘：如以后使用对手全员位置，需明确标为全信息赛后对照，并与仅使用本方五人观测的主实验分开；不能声称这是玩家当时能知道的信息。v1 主表示不读取对手未来位置或事件。

### 13.3 T 方独立晋级门槛

按同一系列拆分规则，比较 T 方 B0、独立图模型和时序目标；不能拿 CT 分数作为 T 方效果。对局势、经济、提前交战、持包状态和地图分层，检查相似回合的相关性与覆盖率。人工规范单独定义，保留无法判定的意图和模式。

只有 T 方独立评测达标，才在页面增加进攻开局过滤、T 方相似回合和地图内模式统计。CT/T 模型分别显示版本、样本与适用范围；不根据模式胜率自动推荐战术。T 方额外训练与评审不包含在前述 CT 净工作日估算中，先按数据可用量估算追加工作。

## 14. 额度、内存与显存控制

执行时读取账户额度与重置时间，按用户当次预算控制工作量；账户即时用量与重置时间保留在本地进度和对话中，不作为公开项目指标。当前开发机为约 16 GiB 内存、8 GiB 显存的笔记本，空闲资源随用户其他工作变化，启动重步骤前重新检查。

实施约束：

- 先单进程、单 Demo、选定 tick 采样，不并行解析，不启动全量轨迹导出。
- 聚类复现和小型训练优先 CPU，数值库线程数先限为 1；默认不申请显存，不安装 CUDA 训练栈。
- 先完成 1 个种子的烟测，再按评测协议跑 5 种子；烟测成功不等于完成实验。
- 开始大步骤前检查可用内存；低于 2 GiB 时不启动新训练，低于 1.5 GiB 时停止追加批次/任务并报告。记录进程峰值，不能以“仅请求几个 tick”推断解析器一定低内存。
- 不关闭用户进程、不清理用户缓存、不改全局代理或系统环境；实验依赖与上游代码隔离在本地忽略目录。
- 若额度不足以完成当前可验证里程碑，先告知用户，保存进度、命令、数据与版本，不把研究结果提前标为通过。账户额度重置不用来自动扩大训练范围，也不自行消耗手动重置权益。
