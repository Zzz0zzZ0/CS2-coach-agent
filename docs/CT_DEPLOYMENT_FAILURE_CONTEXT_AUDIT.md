# CT部署：逐图误差与情境核查

2026-10-25；对应主计划P3。冻结的270个开发模型、465个窗口和既有排名均不变，没有重新训练、下载Demo或分发问卷。

## 1. 逐图误差已经分解

[结构化报告](../datasets/evaluation/ct_reconstruction_failure_audit.json)逐一校验270份结果哈希，重新汇总七组损失；检查各组贡献之和等于总损失差，并与原报告的总体及逐图值对齐。先在窗口内平均三个种子，再在系列内平均窗口，最后等权平均系列。

下表为G4下完整Graph+GRU相对各基线的重建损失降低率。正数表示损失较低，负数表示损失较高；不是战术准确率。各图包含的系列不同，不能直接平均本表来还原总体九系列结果。

| 地图 | 窗口 | 系列 | 相对MLP+GRU | 相对不含运动的图模型 | 相对共同输入图模型 |

| Nuke | 62 | 3 | −8.44% | −2.83% | −3.72% |

Nuke相对共同输入图模型的总损失变化为−0.003703，其中区域组贡献−0.003193，是最大的负向分量；相对不含运动图模型时，最大的负向分量是离地/着地状态组（−0.003691），区域组反而有正向贡献（+0.002754）。因此，当前分解定位的是预测分量，尚未证明退步由速度、高低差或某个输入字段单独导致。

七组沿用原训练的CE/MSE及其尺度；不同组的数值不是可直接比较的物理误差率。不同模型还可能选择不同的整体玩家匹配。以上均为开发集的事后诊断，未进行显著性筛选或新架构选择。

## 2. 现有Demo可以恢复什么

[正式可恢复性记录](../datasets/evaluation/ct_context_availability_report.json)读取全部22个原始Demo，核对Demo哈希、回合终点、冻结终点和已有CT位置、生命及装备值。只解析选定时刻，每次处理一个Demo；使用原有`demoparser2 0.41.3`环境，不更新或改写冻结输入。

| 字段 | 实际覆盖 | 用法和边界 |
| --- | --- | --- |
| 本回合开始前比分 | 465/465窗口 | 按稳定队伍身份累计此前回合，换边后仍对应当前CT/T；不读取本回合结果 |
| CT当前装备总值 | 2,325/2,325时刻 | 可以补充解释资源条件；尚未新增经济档位分类 |
| T当前装备总值 | 2,325/2,325时刻 | 属于完整观战信息，后续若使用必须作为单独条件，不能声称CT当时知晓 |
| 存活CT朝向 | 11,368/11,368存活观测 | 只表示记录的角度；不证明可见性、意图或防守职责 |
| CT已记录投掷 | 2,325个时间前缀，未知阵营计数为0 | 从冻结结束至查询时刻累计；原始投掷位置仅作地理描述 |
| 上回合安包位置 | 233窗口有直接A/B地点记录；210窗口未记录安包；22个首回合无上回合 | 无安包不推断进攻目的地；不使用T方20秒位置多数票替代 |

到20秒共记录2,659次CT投掷，按465个不同回合窗口各累计一次，未把五个重复时间前缀相加。该数字也不是2,659个独立实验样本。

初次读取的投掷下界使用了旧快照中的上一回合终点。正式版本改为当前冻结终点，排除上一回合结束后的投掷；原始探索产物保留在本地，不用于正式统计。来源、脚本与输出哈希均在记录中。

阵亡后的角度字段仍可能更新。[字段核查](../datasets/evaluation/ct_dead_angle_diagnostic.json)中，257个阵亡观测形成158个连续阵亡的采样间隔，其中47个间隔的角度数值变化超过0.0001度；这些是相关的采样间隔，不能当成独立比赛。尚未识别其相机/状态语义，不能一概称为死亡时保留的固定朝向。正式导出按存活状态屏蔽它们，避免将阵亡位置计算为仍在观察的防守点；源Demo及首次读取的原始角度仍保留。若研究死亡前最后朝向或观战信息，需要另行关联死亡时间、相机位置和观察对象。

正式读取耗时56.23秒，进程峰值RAM约934 MiB，全程未使用GPU。该核查不等于原TAGNet的25维上下文已接入，也没有把视角方向当作穿墙可见性。

## 3. 原有六图案例补上情境

[可读对照表](paper/fixed_case_context.md)和[逐时刻数据](paper/manuscript/figures/evidence_context.json)沿用既有六个查询、两种模型和源训练候选库；只补充本回合开始前比分、CT装备及已记录CT投掷，不修改排名或赋予相关性分数。

六个查询按原先“各图冻结索引中的第一个窗口”规则选取，实际都是首回合，不能代表全部经济条件。例如Mirage查询在20秒时CT装备总值4,000、没有记录CT投掷；图模型首位候选来自Inferno第11回合，CT装备29,750，并已记录烟/火/闪/雷为1/1/2/1。两者的情境不同是可核对的事实，是否仍有部署参考价值需要具体判断，不能自动判错，也不能凭几何相似自动判对。

## 4. 后续执行顺序

1. 固定下一项情境对照的假设、字段和公平比较规则：CT团队可得信息与完整观战信息分开；同一候选库；未知值不填成零；不把地点映射为职责。
2. 先做源侧小规模可运行性验证，再决定是否开展下一批开发实验。现有270条件完整保留，不根据当前负结果反复改配方后混报。
3. 完成独立新系列的主终点、精度依据和下载/解析资源预算，再冻结P4。技术重建、模式稳定与战术检索分别验收，不能互相替代。
4. 新排名的独立语义判断仍未具备；旧人工题块继续暂停。不得用旧人工/AI银标分数评价这些新候选。
