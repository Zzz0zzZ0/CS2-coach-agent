# TAGNet 发布权重与回合向量的数值差异诊断

日期：2026-10-22。范围：同一份发布权重、发布数据与发布回合向量的 CPU/GPU 推理诊断；未训练新模型，未评价泛化或战术质量。

## 结论

CPU 严格向量一致性未通过；随后真实 GPU 对照达到原 `1e-5` 阈值。仅开启 cuDNN RNN TF32 时最大误差为 `6.7949295044e-6`，关闭该开关则回到约 `5.95e-4`。本机受控实验已确认 RNN 精度设置是主要偏差来源；原作者完整硬件与软件设置仍未知，不能声称逐位复现。下文保留初始 CPU 诊断，最新 GPU 结果见文末。

`1e-5` 是本项目临时设置的逐元素绝对误差阈值，不是上游对回合向量的精度承诺。上游关于注意力矩阵的 `1e-6` 说明不能直接移用到最终回合向量。继续保留原失败记录和原阈值，把严格一致性、模块一致性和结果稳定性分开。

## GRU 低精度模拟

使用相同图快照表示和同一 GRU 参数，按标准 GRU 公式在 CPU 计算。对指定线性投影的输入和权重施加 10 位尾数的舍入模拟，输出累积继续使用 FP32。它模拟 TF32 的一个数值特征，不等价于真实 cuDNN 内核。

| 路径 | 对发布向量的 RMSE | 最大绝对差 |
| --- | ---: | ---: |
| 手工 FP32 GRU | `1.0780711032e-4` | `5.9486180544e-4` |
| 仅 GRU 输入投影舍入 | `3.2582282300e-6` | `1.0216981173e-4` |
| 仅 GRU 隐状态投影舍入 | `1.0930375166e-4` | `5.9217959642e-4` |
| GRU 两类投影均舍入 | `2.1729393048e-5` | `1.3278424740e-4` |
| 仅情境 MLP 舍入 | `1.0792554735e-4` | `6.0305744410e-4` |

仅输入投影模拟让 RMSE 降低约 96.98%，改善远大于调整批大小或禁用 oneDNN。它强烈支持该投影的原 GPU 精度路径是主要嫌疑；剩余离群差异和实际原始配置仍未解释，不能称为精确复现，也不能把模拟输出用于替换正式推理。

PyTorch 官方明确说明 CPU/GPU 与不同批计算路径不保证逐位相同，TF32 会降低矩阵乘法输入尾数精度。这是机制依据，不是对本次具体原因的直接证明。[数值精度文档](https://docs.pytorch.org/docs/main/notes/numerical_accuracy.html)

## 对已有结果的影响

- 使用发布向量拟合的六个中心，对新 CPU 向量分配：697/697 簇归属不变。
- 两套向量分别以相同 FP64 数据类型、固定 K=6、种子和 K-Means 设置重新聚类：ARI=1，簇大小均为 `[124,109,115,151,136,62]`。
- 排除自身后，全体回合的最近邻 697/697 相同；前五近邻集合 697/697 相同。没有据此声称前五顺序逐项相同。
- 此诊断包括同系列候选，是数值敏感性检查；不是独立比赛检索评测，不代表 nDCG、泛化或教练质量已经通过。

梯度审计另行确认：快照编码器 45 个参数张量有梯度，情境编码器和 GRU 均为 0。这是源版损失的结构性边界，和本次 CPU/GPU 数值偏差是两件事。

## 后续处理

1. 保留严格检查失败；不通过放宽阈值、更换发布向量或重新训练来掩盖它。
2. 发布表示用于忠实论文分析；研究模型的历史与查询表示使用同一固定环境，显式记录 CPU/GPU 与 RNN 精度设置。
3. 分别记录检查点加载、图链路复现、最终向量一致性和结果稳定性：CPU 严格检查失败，选定 GPU 配置严格检查通过，旧失败继续保留。
4. 本次已完成 GPU 对照；若要求逐位精确对齐仍需原始硬件、版本与中间激活。不要把整体 matmul TF32 一起开启，实测会增大偏差。
5. 可以继续进行受控的数据准备与简单基线，泛化训练仍须遵守独立协议；不能把本次数值诊断当作泛化验收。

## 真实 GPU 对照：已完成

环境：RTX 4060 Laptop GPU、驱动 596.21、PyTorch `2.14.1+cu130`、CUDA 13.0、cuDNN 92400，batch=64，权重和输入均与 CPU 对照相同。没有训练或自动混合精度。

首次 GPU 启动因 Anaconda 与 PyTorch 的 OpenMP 运行库冲突中止，没有产出推理结果。随后关闭实验虚拟环境的 system-site-packages，独立安装相同版本的 NumPy、pandas、PyArrow 后成功运行。没有设置 `KMP_DUPLICATE_LIB_OK`，没有替换原有 CPU 环境。

使用新接口分别控制 `torch.backends.cuda.matmul.fp32_precision` 与 `torch.backends.cudnn.rnn.fp32_precision`，未混用旧接口。[官方控制方式](https://docs.pytorch.org/docs/2.14/notes/cuda.html)

本次 PyTorch 峰值显存分配 19.10 MiB、峰值保留 24 MiB，不包含 CUDA 上下文、驱动或其他应用显存。诊断进程峰值工作集约 997.38 MiB，结束时可用系统内存约 3.01 GiB；没有留后台训练进程。首次模式约 0.41 秒，其余约 0.15–0.17 秒，包含传输与冷启动差异，仅作本次记录，不是产品延迟保证。
