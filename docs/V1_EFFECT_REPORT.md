# CS2 Coach V1 效果报告

## 结论

V1 已把原本主要用于社区摘要的 GraphRAG，收敛为可验证的“战队战术分析 + 选手上下文分析”产品链路。统一契约评测 50/50 通过；仅保留旧 community summary 时，能够生成同类结构化答案的查询为 0/50。

## 当前可用效果

| 能力 | 用户输入 | 输出与证据 |
| --- | --- | --- |
| 战队战术画像 | 战队，可选地图、T/CT、对手 | 回合胜率、首杀转化、丢首杀翻盘、补枪、下包后、回防和爆弹候选转化 |
| 战队同条件对比 | 两支战队 + 相同上下文 | 同一分母下的转化指标、关键回合与责任选手 |
| 选手画像 | 选手，可选地图、T/CT、对手 | K/D、首杀胜率、每百回合击杀/补枪/道具及战术参与 |
| 选手同条件对比 | 两名选手 + 相同上下文 | 同条件、同分母指标，避免把不同地图或阵营直接混比 |
| 证据下钻 | 简报中的 `[G#]` 或关键回合 | 原始事件与 silver label 时间线 |
| 胜负回合对照 | 任一可引用回合 | 同地图、同阵营、相反结果的近似回合，以及击杀、死亡、道具、补枪响应和包点差异 |

## 数据与验收结果

- 数据范围：5 支队伍、20 场近期比赛、49 张地图、1,030 回合、5,325 个战术 silver labels。
- 图谱规模：36,360 个节点、107,389 条边、28 个社区摘要。
- 战术查询：30/30 通过；上下文、数值一致性、来源、教练简报、回合下钻、关键回合筛选、胜负对照覆盖率均为 100%。
- 选手查询：20/20 通过；包含总体画像、地图/阵营切片、指定对手切片和双人比较；上下文、数值一致性、来源与回合下钻覆盖率均为 100%。
- 检索延迟：战术查询 p50 231.09 ms、p95 479.71 ms；选手查询 p50 237.00 ms、p95 470.47 ms。
- 消融结果：完整图谱结构化回答 50/50；仅 community summary 为 0/50。
- 工程回归：后端 32/32 tests；前端生产构建通过；浏览器已验证选手自然语言比较、双方证据和回合胜负对照。

原始结果见 [`datasets/evaluation/cs2_coach_v1_report.json`](../datasets/evaluation/cs2_coach_v1_report.json)。

## 这些数字证明了什么

它们证明当前 20 场数据上，查询路由、上下文过滤、SQLite 聚合、结构化简报、来源引用和回合下钻之间保持一致；也直接说明结构化图层相较旧社区摘要提供了新增功能，而不是只增加代码量。

## 尚未证明的部分

- 这不是职业教练人工标注的 gold evaluation，不能证明建议本身达到职业教练质量。
- Silver labels 来自明确规则；其中 Execute Candidate 是弱监督标签，不能当作真实战术意图。
- 指标是描述性统计，不证明某个动作导致胜负。
- 当前样本只覆盖所选 20 场比赛，不能代表队伍的长期版本变化或所有对手。

V1 到此停止扩功能。下一轮应优先做小规模专家盲评或扩大跨赛事样本，而不是继续增加新的统计卡片。
