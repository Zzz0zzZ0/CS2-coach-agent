# 公平消融与独立比赛评测协议草案

状态：同语料工具与无评分试跑已完成，见 [实验记录](FAIR_RETRIEVAL_RUN.md)；首场新比赛 2 图 44 回合已验收，见 [独立比赛记录](UNSEEN_MATCH_PILOT.md)。独立 qrels 尚未审核，正式检索质量评测与多比赛盲测仍待执行。

## 实验问题

在相同数据、过滤条件和输出能力下，关系检索与实体约束能否降低错误回答，同时保持有答案查询的证据覆盖？模型选出的训练优先级是否优于确定性规则，是另一个实验，不混在检索消融分数中。

## 公平消融（第 3 项）

- 固定相同版本的事件文档与源回合 ID；每个回合在不同检索器中保留相同证据边界，不能让一种方法读取完整比赛而另一种只读短句。
- 方法：BM25-only、dense-only、dense+BM25、图路径、直接 SQL 条件聚合。纯文本检索与结构化回答分两张表；需要比较答案时，所有方法进入相同的确定性答案模板。
- 每种方法各测实体约束开/关；过滤条件和 top-k 统一。现有 `vector_only` 实际可能启用 dense+BM25，应在新报告中明确命名。
- 分开报告：有答案查询 Recall@5/nDCG@5，无答案查询误召回率，正例误拒答率，实体/地图/比赛条件正确率，冷/热 p50/p95、索引耗时和存储。
- qrels 至少包含 query_id、source_round_id、relevance、标签依据与审核状态；必须在看召回结果之前制定标签。不要直接用检索器自身的评分函数生成“正确答案”。
- 当前 50 条检索工程用例可作为开发回归，不自动改称 Recall@5 基准。当前结构化契约是产品接口验收，不能替代能力相同的研究消融。

建议先用一小批可人工核对的查询完成评测工具和标签审阅，再扩大样本。报告所有方法的完整结果，包括低分与失败，不只展示最好的组合。

## 独立比赛（第 4 项）

1. 在下载前确定整场比赛隔离规则；不能把同一 BO 系列的地图分到开发与测试两侧。
2. 保留当前 20 场索引与冻结查询，新增比赛不得与现有 match_id 重叠。不要以重新切分当前数据替代真正新比赛。
3. 为每场记录 source_url、match_id、比赛日期（未知就标未知）、Demo SHA-256、地图、解析器版本、规则版本、名单覆盖和排除原因。
4. 新 Demo 复盘任务：新比赛只作当前输入，历史索引不包含它；检查当前事实与引用，不要求从历史索引召回该场不存在的证据。
5. 新语料检索任务：冻结实现后，对保留的新比赛创建独立测试索引；使用独立制定并审核的查询与 qrels。
6. 以比赛为统计分组报告均值与区间；相邻回合不能被当作完全独立样本。开发侧修正后，测试侧的失败历史必须保留。

## 运行前必须具备的材料

- 数据选择清单和去重结果。
- 查询、qrels、标注规范及审核状态。
- 实现提交或源码哈希；图谱、文档与 embedding 文件哈希。
- 每种方法相同的输出契约、过滤规则和 top-k。
- 明确的停止条件：样本缺失/标签未审核时不宣称完成研究评测；所有检索实验禁用远程 LLM。

没有 qrels 的阶段可以运行工程检查和耗时探测，但必须使用对应名称，不报告伪造的 Recall/nDCG。
